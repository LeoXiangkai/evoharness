# Python 通用规则

- 公共函数、类方法和跨模块边界使用准确的类型注解；让类型检查器参与接口变更，避免用 `Any` 掩盖不确定性。
- 不吞异常：禁止裸 `except`；除非能说明恢复边界，不要用 `except Exception: pass`。记录上下文后再抛出或转换为明确的业务错误。
- 文件、锁、连接、游标和响应流使用 `with` 或等价的生命周期管理，确保成功与失败路径都释放资源。
- 不使用 list、dict、set 等可变对象作为默认参数；用 `None` 并在函数体内创建新对象。
- SQL 必须参数化。禁止用 f-string、`format` 或 `%` 拼接 SQL 后传给 `execute`、`executemany` 或 SQL 文本构造函数。
- 关注 ORM 的 N+1 查询：列表接口先规划关联加载和查询次数，避免在循环中逐条访问关系；分页必须有明确上限。
- Pydantic 模型负责边界校验与序列化；确认项目使用 v1 还是 v2 的导入、校验器和配置写法，不混用两套 API。
- Python 代码逻辑文件不得硬编码密钥、口令、令牌和 API key；允许在配置文件中明文配置，并按项目约定注入使用。
- Alembic 使用 autogenerate 后必须人工审查；已发布迁移只追加后续迁移，不直接改写历史文件。
- 依赖和命令使用项目既有解释器/环境；本组件不创建或激活新的环境。
